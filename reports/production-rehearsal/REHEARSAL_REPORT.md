## Source Code Fixes — Root Cause Analysis

### Root Cause 1: `editorialColors()` in `directed-scene.jsx` did not validate `text`/`textDark` colors
The `editorialColors()` function only applied `ensureTextContrast()` to `accentText` and `quiet`, but `text` and `textDark` were assigned raw palette colors without contrast validation. This meant text could be rendered in colors that fail WCAG AA against the background.

**Fix:** Apply `ensureTextContrast()` to `text`, `textDark`, `subdued`, and `accent` return values in `editorialColors()`.

### Root Cause 2: `themeFor()` in `full-canvas.jsx` did not validate `ink` color against ground
`themeFor()` returned `INK` (`#0B0B0C`) or `#F5536B` without validating against the ground color. On white ground, `INK` (`#0B0B0C`) is fine, but `INK_SOFT` (`#8E8E93`), `MID` (`#A7A7AD`), `LIGHT` (`#DADADF`) used directly as text colors could fail on white ground.

**Fix:** `themeFor()` now computes `isDark` from ground luminance and validates `ink` via `ensureTextContrast()` against the actual ground color for both light and dark themes.

### Root Cause 3: `popState()` in `kinetic.js` returned opacity < 1 during entrance
`popState()` returned `o: clamp01(t * 2.2)` which faded text from transparent during entrance. Partially transparent text blended with background, reducing contrast below 4.5:1 even when base color passed.

**Fix:** `popState()` now returns `o: 1` always. The pop animation comes from scale/position only, not opacity.

### Root Cause 4: `Label` component in `composed-scene.jsx` used `ed.quiet` on white ground
`ed.quiet` was validated against dark ground but used on white ground for label text, resulting in low contrast.

**Fix:** `Label` uses `#0B0B0C` on white ground instead of `ed.quiet`.

### Root Cause 5: `frame-audit.js` sampled the dominant foreground color, which could be a dark graphical element rather than text
The audit sampled the most frequent foreground color in the headline/caption zone. If a dark graphical element (bar, panel) dominated the zone, it was mistaken for text and flagged as low-contrast.

**Fix:** `estimateForeground()` now selects the foreground color with **maximum contrast** against the background (not the most frequent). This isolates actual text (which is typically high-contrast against its ground) from dark graphical elements.
