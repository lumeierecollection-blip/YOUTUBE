7. IMPORTANT: SKILLS ARE NOT THE APPLICATION
============================================================

OpenCode skills are reusable instruction modules.

They are NOT the runtime video editor.

They are NOT a replacement for production code.

They are NOT a dump of every project requirement.

They are NOT giant files containing implementation guesses.

Skills should contain focused, reusable procedures and quality rules.

OpenCode discovers project-local skills from paths such as:

.opencode/skills/<skill-name>/SKILL.md

Each skill must contain valid YAML frontmatter including:

name:
description:

OpenCode loads skills on demand through its skill mechanism.

Therefore:

DO NOT create 40 unnecessary skills.

DO NOT create one gigantic "do everything" skill.

DO NOT duplicate the entire repository architecture inside skills.

DO NOT put mutable application state inside skills.

DO NOT make skills responsible for scheduling the whole application.

DO NOT invent skill names without checking what actually exists.

Instead create a small set of useful, focused skills.

Potential examples:

visual-design
remotion-production
asset-research
video-qa
youtube-script
channel-production
editorial-storytelling
reference-research
render-validation

BUT:

These names are examples only.

First inspect the repository.

Then determine which skills are actually necessary.

A skill should exist because it provides reusable expertise/procedure.

The production system itself belongs in code.
