That beat is the map key added in 3f51385f - "[ladder] ch-26 beat 6: names
"Australia" -> a key on the Ireland map that covers it". So this is my own code,
and it was wrong: the key sized its plate with `16 + name.length * 15` and set the
type at a fixed 20 px. That guess is wrong for any name whose real width is not
about 15 px per character, so the name ran past its own plate and the frame
clipped it.

The key now measures the name with the same measure() the type system already
uses and steps the size down until it fits the space it has. A word is never cut
mid-string.

NOT YET VERIFIED. This compiles (esbuild) and the suite is 757/0, but no render
of the new key has been inspected, and this change has NO regression test yet.
