# SFX Sourcing Skill

## Purpose
Ground sound design in two things: real research on how SFX are actually
used effectively, and real audio files pulled from genuine sources —
never a synthesized stand-in described as "a whoosh sound" with nothing
behind it.

## Process

### 1. Usage research (per style/niche)
Search for how sound effects are used effectively in this style of
content: timing relative to cuts/captions/reveals, subtlety vs. punch,
which categories fit which moments (whoosh on transitions, soft ding on
a key point, riser before a reveal, impact on a hard cut). Different
styles call for different densities — minimal wants sparse/subtle use,
motion-graphics can carry more.

### 2. Real file sourcing (via GitHub)
Search GitHub for actual open-source/free-license sound-effect
repositories (e.g. CC0 or MIT-licensed SFX packs). For each candidate
repo:
- Confirm the license actually permits the intended use (including
  commercial/monetized YouTube use where relevant)
- Download the real files, don't just note that the repo "has good sounds"
- Log the source repo, license, and file path for each one used

### 3. Build a tagged local library
Organize sourced files by use-case (transition, emphasis, reveal, impact,
ambient) per style, so remotion-render can pull from real files rather
than needing a fresh search every time.

## Rules
- Never invent, describe, or use a sound effect that wasn't actually
  downloaded from a real, verified source.
- Never use a file whose license doesn't clearly permit the intended use —
  skip it and find another if there's any doubt.
- Keep an attribution/license log alongside the audio library for future
  auditing.
- Apply sparingly per the usage research — more SFX is not automatically
  better; match what actually works in this style/niche.
