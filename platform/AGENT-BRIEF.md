# Brief for every channel and engine agent

Read `platform/README.md` first. It defines what you own. Read `CLAUDE.md` too.

## Hard limits

- Never open, modify, stage, commit, rename or delete `task.txt` or `debug_creds.js`. Do not modify `server.js`, `rix.json` or `signal_aggregator/lib/**`.
- Edit only the paths you own. Need something else changed? Put it in your report.
- Nothing uploads to YouTube. You have no reason to touch YouTube credentials, and must not.
- Never merge to `main`. Never force-push. Never cancel, re-run or disable a workflow you did not start.
- Never trigger `autopilot.yml` or push to `automation/kick`.
- The owner's PC has about 1.4 GB of free memory. Do NOT run Remotion, Chrome, Blender, ffmpeg batch work or `npm install` locally, and do not use `run_in_background`. Local work is editing files, `node --check`, and small `node --test` runs. Rendering happens on GitHub.
- To use `node` modules locally for a unit test, junction them: `cmd //c mklink /J node_modules C:\Users\info\YOUTUBE\node_modules`. Never commit the junction.
- Wait for GitHub with a bounded foreground check: `timeout 540 gh run watch <id> --interval 45 >/dev/null 2>&1`. Repeat if needed.
- Do not fabricate facts, statistics, quotations, images or sources. Every fact in a sample comes from a page you actually fetched; record its URL. Do not weaken a test or gate to pass.

## How to produce real output

1. `git switch -c preview/<key>` from the current `feat/platform` commit. Commit only your paths.
2. Push: `git push -u origin preview/<key>`. That runs `.github/workflows/channel-preview.yml` on GitHub for your channel, calling your `platform/channels/<key>/preview.mjs`. Each later push runs it again. Find the run with `gh run list --branch preview/<key> --limit 1`.
3. Stages are published to branch `automation/previews` as they finish, at `previews/<key>/<run>/`. The MP4 is in the Actions artifact: `gh run download <id> -D <dir>`.
4. Download your contact sheet and look at the actual frames with the Read tool. Fix what is wrong and push again. A render you have not looked at does not count.

`preview.mjs` receives `{ key, runId, outDir, tools, entry }`. `tools` is in `platform/preview/lib.mjs`: `stage(name, status)` publishes progress, `write`, `renderComposition`, `renderTimeline`, `voice`, `contactSheet`, `durationOf`.

Call `tools.stage(...)` after each stage so previews appear as you go. Write these into the run when you have them: `story-outline.md`, `script-draft.md`, `scene-plan.json` (must satisfy `platform/contracts/scene-plan.schema.json`), `contact-sheet.jpg`, `preview.mp4`, `voice-preview.mp3`, `qa-report.json`.

Channel-specific packages go in `platform/channels/<key>/deps.json` or `requirements.txt` and are installed only for your run.

## Visual standard

- Video is 1080x1920, 30 fps, at most 30 s for a Short, measured from the final MP4.
- Explanatory motion graphics default to a WHITE background. Documentary photos, maps, 3D, space, football pitches and interfaces use what their subject needs.
- A video must not look like one template refilled. Every scene has a stated visual purpose. Someone watching with the sound off should learn from the picture.
- The picture shows what the sentence says: the country named, the region named, the actual feature, the actual data.
- Charts use real sourced values, one unit, and start at zero.
- Captions must stay legible and must not collide with graphics.

## Specialist skills are the point

For each repository or skill assigned to you: read its README, install steps, real skill instructions, examples, dependencies and licence, and find out what it actually does and what it takes in and puts out. Pin the exact commit. Record all of it in `platform/channels/<key>/SKILLS.md`.

Use the specialist tool for what it does best. Do not rewrite it as generic animation code because that is easier. If a Claude-only skill cannot run unattended, extract the reusable part (templates, parameters, code) into a script that runs on GitHub with no Claude session. If a tool is unusable, say why with evidence (licence, build failure, output quality) and use the next best option.

Claude Code must not be needed to make a future video.
