## Verified locally (real renders, not code reading)

- `scripts/qa-canvas-render.mjs` renders a 20-beat plan that uses all thirteen
  compositions, both anchoring variants, the snap-in year, the emphasis word,
  the vertical beat and two dark beats, on the real renderer with the vendored
  fonts. Frames were inspected.
- The real audit (`local-audit.cjs --canvas-only`) run on that rendered video:
  `canvas-fit`, `canvas-accent`, `canvas-type` (no composition twice in a row,
  two dark beats, 19/20 beats with two type roles, nothing centred, sentence
  case), `canvas-texture` (grain on every beat, dark beats dark) and
  `motion-tiers` PASS, and after one fix so does `canvas-coverage`:
  MAP-CENTERED first measured 50% (its linework was too faint to count as
  content), so its borders and fill were strengthened, the video was re-rendered
  and re-audited (min coverage 61%). All six canvas checks pass on that file.
- Render cost of the 80 px hero shadow, measured A/B at CI's 0.75 scale: 35.5 s
  vs 28.5 s per 180 frames (+25%). `plan.hero_shadow === false` turns it off.
- Unit tests, all passing: `test-typography` (35), `test-canvas-layout` (162
  layouts), `test-canvas-style` (18), `test-canvas-grounding` (30),
  `test-composition-rotation` (11), `test-plan-gates` (33), `test-tts-normalize`.

## NOT verified

- **Any CI run.** No planner call (Gemini) has produced a plan with the new
  visual types; the rotation and the new gates are tested on sentences, not
  on a model's plan.
- **Wikimedia lookups.** The container cannot reach Wikimedia, so the DOCUMENT
  and MONEY resolvers, the building detection behind ARCHITECTURE, and the
  acronym table were exercised only through their file-name filters. Expect
  DOCUMENT and MONEY to resolve rarely and fall back to typography (logged).
  The showcase uses a repo fixture photo for every photo-family beat.
- **The voiceover.** The showcase is silent, so list-item timing (items appear
  as the narrator says them) is checked only on made-up word timings.
- **Whether the scripts have enough to show.** No renderer can draw a sentence
  that states nothing visualizable; the no-repeat rule falls back to
  TYPE-SPLIT / TYPE-FULL alternation, which is honest but is still typography.

## Departures from the brief (each argued in the commit that made it)

- Headline size floor 88 px (a 160 px word is wider than a 340 px cell);
  "1-2 cells" read as 1-2 grid rows.
- Numbers are never cropped by the frame edge (a cropped digit misstates the
  figure); a very long numeral shrinks below the band instead.
- Row 3 of the grid is the caption row; content lives in rows 0-2.
- NUMBER-FULL and TYPE-SPLIT are additions to the composition list, so that
  two text-only sentences in a row can both satisfy the no-repeat rule.
- A section folio ("03 / 08") is the second type role on a statement beat with
  no lead-in — structure, not a claim. (Scripts map to sources per script, not
  per sentence, so a per-beat SOURCE label would not have been truthful.)
- The count is "60% of the beat" (4.2) while its onset follows the
  choreography (4.5, from 0.5 s).
- Two existing checks changed rules because they contradicted the design:
  `frames-centered` now runs for paper videos only; the white-ground verify is
  > 222 (was 240) because the vignette darkens the crop it measures.
- A DOCUMENT beat does no OCR and never claims to highlight a passage of the
  scan: its highlighter band sits behind the beat's own headline.
